# neo 桌面版自编译 sing-box 内核 · 说明（2026-10-18）

## 这是什么

`runtime\sing-box.exe` 是**自编译**版本（非上游官方二进制），用于让 neo 的 TUN 模式
也能做多节点并发。官方 sing-box 1.14.2 **没有负载均衡出站**，实测
`sing-box check` 对 `{"type":"balancer"}` 报 `unknown outbound type: balancer`，
因此必须自编译。

本目录保存的是**可复现的源码补丁**，防止将来重新编译时丢失改动。

## 产物清单

| 文件 | 说明 |
|---|---|
| `balancer.go（neo桌面版-已移除3倍门槛）` | 打补丁后的完整文件，直接替换上游同名文件即可 |
| `sing-box.exe`（在 `..\..\runtime\`） | 编译产物，版本串 `1.14.3-noGate` |
| `sing-box.exe.orig-official`（在 `..\..\runtime\`） | 官方原版备份，可随时回退 |

## 编译来源与前提

- 源码：`E:\neo-app\src\sing-box`（手机版工作区的 v1.14.x + balancer 补丁快照，**只读借用**）
- 编译器：`E:\neo-app\tools\go1268\bin\go.exe`（go1.26.8）
- 依赖缓存：`E:\Cache\gocache\pkg\mod`（已齐备）
- 源码本身**未做任何修改**（`go.mod`/`go.sum` 也保持原样，编译用 `-mod=readonly`）

### 编译命令（实测可用）

```powershell
$env:GOPROXY='https://goproxy.cn,direct'
$env:GOMODCACHE='E:\Cache\gocache\pkg\mod'
$env:GOCACHE='E:\Cache\gocache'
$env:GOTOOLCHAIN='local'      # 用本机 go1.26.8，不触发工具链下载
$env:CGO_ENABLED='0'
$env:GOFLAGS='-mod=readonly'   # 绝不改动源码目录的 go.mod

# ★ 关键：标签里必须去掉 badlinkname 与 tfogo_checklinkname0（原因见下）
$tags = (Get-Content "release\DEFAULT_BUILD_TAGS_OTHERS" -Raw).Trim() `
        -replace ',badlinkname','' -replace ',tfogo_checklinkname0',''

# ★ 关键：-X 注入版本号，必须作为独立参数（放进单引号字符串里 PowerShell 不解析）
go build -trimpath -p 6 -tags "$tags" `
  -ldflags "-X github.com/sagernet/sing-box/constant.Version=1.14.3-noGate -s -w" `
  -o sing-box.exe ./cmd/sing-box
```

## ★ 两个必须踩过的坑（否则编译失败或功能缺失）

### 坑 1：`tfogo_checklinkname0` 与 Go 1.26 不兼容

报错：

```
link: github.com/database64128/tfo-go/v2: invalid reference to net.(*netFD).init
```

原因：`tfo-go` 用 `go:linkname` 挂钩 Go 内部的 `net.(*netFD).init`，
而 **Go 1.26 改了这个内部结构**，上游尚未适配（升级 tfo-go 到 v2.4.2、v2.3.3 均无效，
因为那段 linkname 代码仍在）。

**解法：编译标签里去掉 `badlinkname` 和 `tfogo_checklinkname0`。**

代价已查清（可接受）：

| 去掉的东西 | 实际影响 |
|---|---|
| `tfogo_checklinkname0` | 只损失 **Windows 的 TCP Fast Open 优化**；代码走 stub（`comptimeDialNoTFO=true`），连接仍正常 |
| `badlinkname` | 影响 `common/badtls`、`ktls`(仅 Linux)、`libbox`、`oomkiller` —— 均为**实验性**模块，且各自都有 stub 回退实现 |

实测核验：核心 TLS 出网正常（`bing` HTTP 302、`github` HTTP 200），
TUN、hysteria2、tuic、balancer 出站全部可用。

### 坑 2：版本号注入

`-ldflags "-X ...".` 若写成 `-ldflags "-X 'pkg=ver' -s -w"`（X 参数带引号），
PowerShell 解析后 `-X` 会与值分离，导致版本显示 `unknown`。
正确做法是 `-X` 与 `pkg=ver` 之间用空格、**不要**给值再套引号。

## 本补丁相对上游快照的改动

**仅一处**：删除了 `protocol/group/balancer.go` 里 `healthyMembers()` 中的
「质量门槛」——原本会剔除比最快者慢 `balancerMaxDelayRatio(=3)` 倍的成员。

删除依据（用户明确要求）：

> 「我要的并发是所有节点都能一起工作，为什么要踢出去？慢还不是有速度，
> 只要保证总体快不就行了？」

技术理由：多连接场景下总吞吐是各节点带宽的**相加**，慢节点贡献较少但仍在贡献；
踢掉它等于主动放弃那部分带宽。桌面版的「加权 / 均衡」两个模式已从**配置层**
（份额）实现「快节点多吃、慢节点打辅助」，比在池内做二元生杀更贴合预期。

**保留的**仍只是「健康性」筛选：只有有未过期探活成功记录的成员才进池
（`delayOf(detour) > 0`）。这排的是**探测失败的坏节点**，不是慢节点 ——
与「慢的也要打辅助」不冲突。

### 直接证据（同机受控对照）

把门槛临时改成 2 倍（使其必然触发）与完全无门槛对比，同一份配置、同一批节点：

| 内核 | 池内成员 | 最快 | 最慢 |
|---|---|---|---|
| 带门槛（2× 必触发） | **6 个** | 315ms | 338ms |
| **无门槛（本补丁）** | **14 个** | 293ms | 749ms |

带门槛时 8 个 ~720ms 的节点被全部剔除；无门槛时含 749ms 者全部保留。

## 配套：两个必须显式设置的配置参数

这两个是 **neo 的 C# 配置层**（`SingBoxConfigBuilder.BuildTunMulti`）负责写入的，
与内核补丁配套，缺任一都会让「真并发」失效：

| 参数 | 不设的默认行为 | 后果 | 正确值 |
|---|---|---|---|
| `pool_size` | 内核默认 **3** | 池被截断成最快 3 个 | = 成员总数 |
| `sticky_key` | 默认 `[process, domain]`（粘滞**默认开启**） | **同一域名/进程的连接全粘死到一个节点**（实测 12 条并发下载同一 URL，采样 32 次全是 proxy0） | 默认 `["none"]`；仅游戏白名单时用 `["process"]` + `sticky_processes` |

## 升级内核时的注意事项

1. 上游 sing-box 若发布新版，需重新按上述流程编译，并把本补丁**重新应用到新的 `balancer.go`**
   （上游若重构了 `healthyMembers` 函数，锚点会变，需手工核对）。
2. 若将来上游原生支持「按份额分摊」的分组出站，可考虑弃用本补丁。
3. **不要**用官方 sing-box 覆盖 `runtime\sing-box.exe`：neo 的能力探测
   （`ConnectionService.SingBoxSupportsBalancer`）虽会检测并自动退回单节点、
   不会导致 TUN 断网，但 TUN 并发会静默失效。

# 追加（2026-10-21）：完整补丁集 + 一键可复现构建 + 发布要求

## 为什么之前「只补一个 balancer.go」编不过
上游 v1.14.3 没有 balancer 出站：`option.BalancerOutboundOptions`、`C.TypeBalancer`、
`C.BalancerStrategy*` 等符号都不存在。本文上面写的「仅一处改动」是相对**手机版快照**
（`E:\neo-app\src\sing-box`，该目录现已不存在），不是相对上游。

## 补丁集（已入库，构建脚本自动应用）
| 文件 | 作用 |
|---|---|
| `files/protocol/group/balancer.go` | balancer 出站本体（相对手机版快照删了 3 倍质量门槛） |
| `files/option/balancer.go` | `option.BalancerOutboundOptions`（JSON 字段映射） |
| `files/constant/balancer.go` | `TypeBalancer` / 策略 / sticky / 默认值常量 |
| 构建脚本内一行插入 | `include/registry.go` 注册 `group.RegisterBalancer(registry)`（带命中数断言） |

## 一键构建
```powershell
pwsh -NoProfile -File tools\build-singbox.ps1
# 本机 go 低于 go.mod 要求时：
pwsh -NoProfile -File tools\build-singbox.ps1 -AllowToolchainDownload
```
产物：`dist\kernel\neo-singbox-1.14.3-noGate-windows-amd64.zip` + 同名 `.sha256`。
脚本自带自检：版本串含 `1.14.3-noGate`、最小 balancer 配置 `sing-box check` 通过。

## 发布要求（2026-10-21 起，应用端强制）
- 资产名必须是 `neo-singbox-<内核版本>-windows-amd64.zip`；
- **必须**同时上传 `<资产名>.sha256`（内容：`<64位hex>  <zip文件名>`）；
- 缺 .sha256 时应用会直接中止安装并提示，不再冒「装了未验证二进制」的险。
